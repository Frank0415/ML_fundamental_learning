## 一、旧引擎概况

`minivLLM/` 是一个总计约 900 行 Python 源码的小型 LLM 推理引擎，专为 Qwen3-0.6B 设计。其技术栈为 Python 3.13 + PyTorch 2.11 + Transformers 5.8，无 C++/CUDA/Triton，无任何扩散相关模块。它是 `diffusion/` workspace 下的一个独立 Git 仓库，与扩散项目平级存在，不构成依赖关系。

核心事实（已在 T2 报告第 6 节确证）：

- 14 个审计模块中，5 个 Yes、3 个 Partial、6 个 No
- 唯一可直接复用的代码是 `activation.py` 中的 `SiluAndMul`（11 行）：`silu(x) * y`
- 存在已确认 Bug：`Qwen3FFN.act_fn = None`，gated activation 从未连接到前向传播
- Paged attention 仅有占位字段（`block_tables`、`slot_mapping`），无任何实际 kernel 实现
- 采样循环仅有 greedy argmax，无 temperature/top-k/top-p
- 无 timestep embedding、noise scheduler、denoising loop、VAE 集成

T2 最终结论：**C（完全不适合，新建 `diffusion_engine/`）**，次选 B（仅复用 SiluAndMul + 代码风格参考）。

## 二、14 个模块逐项审计要点

以下按模块分别说明"旧引擎有什么"、"扩散需要什么"、"为什么不兼容"。

### 2.1 Tensor Abstraction — No

旧引擎直接使用 `torch.Tensor`，无任何自定义张量包装类。扩散引擎如果需要多精度/量化/分布式张量抽象，minivLLM 无法提供任何基础。该结论不变。

### 2.2 Model Loader — Partial

旧引擎依赖 HF `AutoConfig` 和 `AutoModelForCausalLM` 加载模型。`_load_hf_weights_into_mini()` 函数做的是 HF state_dict → mini 命名空间的手动映射，不是通用 loader。扩散模型（DiT/MMDiT）的权重格式不同于 LLM，需要完全重写。

### 2.3 Transformer Block — Yes（结构可参考，逻辑不兼容）

`Qwen3DecoderLayer` 实现了 Pre-Norm decoder 结构（input_layernorm → attn → post_layernorm → mlp），residual 作为显式参数传出传入。这是良好的工程习惯，扩散引擎的 DiT block 可以参考这一结构范式。但 DiT 需要 AdaLN-Zero 注入 timestep conditioning，当前 block 的 RMSNorm 和 causal attention 都需要替换。

### 2.4 Attention — Yes（GQA + causal，不可用于 DiT）

`attention.py` 的 `Attn` 类实现了 Q·K^T / sqrt(d_k) → softmax → matmul V 的标准 attention 流程，`Qwen3Attn` 在此基础上叠加了 GQA（`repeat_kv`）、causal mask 和 QK-Norm。核心公式是通用的，但架构设定完全针对自回归语言模型。详见下一节"三个为什么"。

### 2.5 MLP / FFN — Partial（SiluAndMul 可复用，FFN 有 Bug）

`SiluAndMul`（`activation.py`）实现 `silu(x) * y` 的 gated activation，与扩散 FFN 的 SwiGLU 完全一致，是本次审计中唯一可直接复用的代码。但 `Qwen3FFN` 的 `self.act_fn = None` 导致 forward 会抛出 `TypeError`，说明该模块从未被完整端到端测试。

### 2.6 Norm — Yes（仅参考，不直接复用）

`RMSNorm` 实现紧凑（17 行），支持 residual 融合的 API 设计（`forward(hidden_states, residual=None)`）值得参考。但扩散 transformer 需要的是 AdaLN（根据 timestep embedding 动态生成 scale/shift 参数）或 GroupNorm，而非 RMSNorm。

### 2.7 RoPE — Yes（不可直接复用）

`RotaryEmbedding` 实现了标准的 cos/sin 缓存 + `@torch.compile` 加速，质量不错。但扩散模型不使用 RoPE——DiT 的 latent patches 通过 2D sinusoidal position embedding 或可学习 position embedding 注入位置信息，与 RoPE 的旋转方案完全不同。

### 2.8 Timestep Embedding — No

这是扩散引擎最核心的组件之一，旧引擎完全不存在。扩散模型需要将标量噪声时间步 t ∈ [0, 1000] 映射为高维特征向量，注入到 transformer block 的 AdaLN 层中。此模块必须从零实现。

### 2.9 Scheduler / Batch Scheduler — No

旧引擎的 `config.py` 有 `max_num_seqs` 和 `max_num_batched_tokens` 两个配置字段，但没有任何调度逻辑。扩散引擎的"调度"概念完全不同：noise scheduler（DDPM/DDIM/Flow Matching）控制去噪过程的 alpha/beta schedule，与 LLM 的请求调度无交集。

### 2.10 Sampling Loop — Partial

`validate_model.py` 中有一个 8 步的 greedy decoding loop（每步 `last_logits.argmax(dim=-1)`），仅用于 HF 对比测试。无 temperature/top-k/top-p，无 KV cache 增量填充（每次重新构建完整 `input_ids`）。扩散采样循环（从纯噪声开始，T→0 步逐步去噪，每步更新全部 latent）与 LLM 的逐 token 生成完全不同。

### 2.11 Memory Manager — No

`config.py` 有 `gpu_memory_utilization` 字段但无任何代码使用。扩散引擎需要显存管理，但管理对象是 activation checkpointing、latent buffer、模型权重 offloading，与 LLM 的 KV cache 内存分配完全不同。

### 2.12 KV Cache — Yes（扩散不需要）

`KVCache` 类使用连续预分配 buffer，支持 `write(layer_idx, positions, k, v)` 和 `read(layer_idx, end_pos)`。这是为 LLM 设计的：token 序列一次生成后 K/V 不变，可跨 step 复用。扩散的 denoising 过程每步产生全新的 latent，上一步的 K/V 对下一步无意义，因此 KV cache 对扩散项目无用。

### 2.13 Paged Attention — No（仅占位）

`context.py` 定义了 `block_tables` 和 `slot_mapping` 字段，但全文搜索无任何 attention kernel 使用它们。这些字段是从 vLLM 接口设计中抄袭的占位符，背后的分块逻辑从未实现。

### 2.14 Context / Config — 仅参考 dataclass 写法

`config.py` 和 `context.py` 的 dataclass 组织方式可参考，但字段完全面向 LLM（`is_prefill`、`cu_seqlens_q`、`context_lens` 等），扩散需要 `num_timesteps`、`noise_schedule`、`patch_size`、`cfg_scale` 等完全不同的配置。

## 三、三个核心"为什么"：机制层面的不兼容解释

### 3.1 为什么 GQA + causal attention 不能直接用于 DiT/MMDiT

LLM 的自回归解码有两个基本约束，它们共同塑造了 attention 的设计：

**GQA（Grouped Query Attention）** 是为了节省 KV cache 显存。LLM 推理中 KV cache 的大小 = 2 × num_layers × seq_len × num_kv_heads × head_dim。通过让多个 Q heads 共享一组 K/V heads（num_kv_heads < num_heads），可以成倍压缩 KV cache 占用。这个优化的前提是"KV cache 需要长期存储"。

**Causal mask** 是为了保证自回归解码的因果性——第 i 个 token 只能看到位置 0 到 i 的信息。这是语言模型的本质要求，不是可选的优化。

DiT/MMDiT 的 attention 场景完全不同：

- **无因果性**：扩散去噪是对整张图的 latent patches 做并行处理，所有 patches 需要互相 attend。不存在"未来 patch 不可见"的约束。
- **无 KV cache 需求**：如 3.2 节所述，denoising 每步 latent 全刷新，没有需要节省的跨步 KV 存储。GQA 在这里失去了优化意义。
- **joint attention（MMDiT）**：MMDiT 的 attention 不是单纯的自注意力，而是 text tokens 和 image tokens 之间的双向联合注意力（joint attention），需要处理两种模态的 token mixing。

结论：minivLLM attention 的核心设计决策（GQA、causal mask、RoPE）都服务于 LLM 的约束，这些约束在扩散场景中不存在。除 Q·K^T / sqrt(d_k) → softmax → matmul V 这一核心公式外，两个 attention 实现的架构差异是根本性的。

### 3.2 为什么 LLM KV cache 不能直接套到 diffusion

LLM 推理的 KV cache 依赖于一个关键前提：**过去生成的 token 的 K/V 值在后续解码步骤中保持不变**。

具体来说：
- Step 0：生成 token_0，计算 K0、V0，存入 cache
- Step 1：生成 token_1，需要 K0+Q1 → attention scores。K0 不变，只需计算 K1、V1
- Step N：生成 token_N，复用 K0 ~ K_{N-1}，只需计算 KN、VN

这就是 KV cache 的核心价值——避免每步重新计算所有历史 token 的 K/V。对于生成长度为 1000 的文本，从 O(T^2) 降为 O(T)。

扩散的去噪过程不满足这一前提：

- Step t（噪声水平 σ_t）：输入 latent x_t，通过 DiT 计算 K_t、V_t
- Step t-1（噪声水平 σ_{t-1}）：输入 latent x_{t-1}。**x_{t-1} 与 x_t 是完全不同的张量，不是"在 x_t 上追加新 tokens"。**
- 因此 K_{t-1} ≠ K_t，V_{t-1} ≠ V_t。上一步的 K/V 对下一步无任何重用价值。
- 去噪过程中 latent 的 shape 是固定的 `(B, C, H, W)`（latent 空间），每一步的"序列长度"（patch 数）相同，不存在递增式的新 token。

扩散的序列长度是固定的（如 256 个 patches），每步的 attention 都是对固定长度的全序列计算。这是一个 O(T) 的迭代过程，不是 O(T^2) 的自回归过程。

因此，**KV cache 对 diffusion 是纯粹的冗余代码**。`minivllm/core/kv_cache.py` 的 `KVCache` 类可以完全忽略。

### 3.3 为什么 RMSNorm / RoPE 不能直接套到 diffusion

**RMSNorm → AdaLN**：

RMSNorm 是一个无参数的归一化层（仅学习一个 scale 参数 γ）：`RMSNorm(x) = x / RMS(x) * γ`。它的行为在训练后是固定的。

Diffusion transformer（DiT/MMDiT）使用 **AdaLN-Zero**（Adaptive Layer Normalization with zero-initialization）：
- 从 timestep embedding 和条件 embedding（如文本）生成两个向量：α（scale）和 β（shift）
- 每个 transformer block 的归一化变为：`AdaLN(x, α, β) = α * LayerNorm(x) + β`
- 零初始化策略使网络在训练初期表现为恒等映射（α 初始化为 0），稳定训练

这两个机制的核心差异在于：RMSNorm 的 scale 参数是静态的（训练好的权重），而 AdaLN 的 scale/shift 参数是动态的（由 timestep 和条件输入实时生成）。将 RMSNorm "改造"为 AdaLN 需要完全重写 forward 逻辑，并引入 timestep/condition embedding 的注入路径。改动幅度等同于重写。

**RoPE → 2D Sinusoidal Position Embedding**：

RoPE 通过旋转变换将位置信息编码到 Q/K 的内积中：`Attention(Q, K) = (R_θ(m)·Q) · (R_θ(n)·K)^T = Q·R_θ(n-m)·K^T`。这个方案的优势是位置信息以相对形式出现（n-m），适合可变长序列。

扩散模型处理的是二维 latent 网格（如图像的 4×64×64 在 patchify 后变成 (64/2)×(64/2)=32×32=1024 个 patches，或视频的 spacetime patches）。位置信息必须编码二维坐标（或三维），RoPE 的一维旋转不适用。DiT 使用：
- 2D sinusoidal embedding：为每个 patch 的 (row, col) 坐标生成独立的 sinusoidal 编码
- 或可学习的 2D position embedding

这两种方案在实现上与 RoPE 的 `cos_θ·x1 - sin_θ·x2` 旋转变换完全不同。`rope.py` 的代码不能为扩散的位置编码提供任何可直接迁移的逻辑。

## 五、审计结论

**最终结论：C（完全不适合，新建 `diffusion_engine/`），次选 B（仅复用 SiluAndMul + 代码风格参考）。**

minivLLM 是一个自回归语言模型推理引擎，其核心设计决策（GQA、causal mask、RoPE、KV cache、自回归采样）全部围绕"逐 token 生成文本"这一任务。扩散模型（DiT/MMDiT）的核心任务（全序列并行去噪、timestep conditioning、full attention、noise schedule）与 LLM 推理在机制层面不存在可复用的交集。

旧引擎 900 行代码中，唯一可直接通过复制复用的代码是 `SiluAndMul`（11 行）。其余模块最多作为 PyTorch 编码规范和模块组织方式的风格参考。

**后续任务（T11/T12/T16）的关键指引**：

- **T11（DiT 实现）**：attention 应从零写，不要从 `minivLLM Attention` 改造。Qwen3Attn 的 GQA + causal mask 逻辑是负担，不是资产。
- **T12（CFG 采样）**：采样循环从零写，不要参考 `validate_model.py` 的 greedy loop。扩散的 denoising 从 T → 0 完全不同于自回归的逐 token 生成。
- **T16（系统优化）**：主优化方向不是 KV cache（扩散不需要），而是 activation checkpointing、latent buffer 管理和 CFG 双 forward 合并。
