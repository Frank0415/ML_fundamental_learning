### ① Scaling Rectified Flow Transformers for High-Resolution Image Synthesis（SD3 / MMDiT）

#### 为什么对现代 diffusion 推理重要（≤100 字）

这是 **rectified flow + MMDiT** 的定义论文。它建立了现代 diffusion transformer 推理的标准范式：用 MMDiT 的 joint attention 同时处理 text token 和 image latent token，在 vector field 层面做 CFG。理解 SD3 推理是理解 FLUX、Sana、所有视频 DiT 的前提。

#### 模型类型：文生图

#### 核心架构

- **denoiser**：MMDiT（Multi-Modal Diffusion Transformer），不是 U-Net。text token 和 image latent token 通过独立的 MLP 投影后 concat 进入 joint attention block。
- **latent 表示**：VAE latent，8× 下采样，16 通道。
- **text conditioning**：双 text encoder（CLIP-L + CLIP-G + T5-XXL）。T5 是可选的（SD3 Medium 可省略）。text token 和 image token 在 MMDiT 中以双流方式交互，text 流权重由 text encoder 类型决定。
- **timestep/sigma conditioning**：timestep embedding 通过 Fourier features 编码后注入 adaLN-Zero（生成 scale/shift/gate 来调制 norm 和 MLP 输出）。
- **attention 结构**：full attention（所有 token 互相 attend）。在 MMDiT 中 text token 和 image token 通过统一的 QKV 投影进入同一个 attention。
- **VAE**：16 通道 VAE（同 SDXL），8× 下采样。区别于之前 SD1.x/2.x 的 4 通道 VAE。

#### 推理数据流

1. prompt → tokenizer → CLIP-L / CLIP-G / T5-XXL → text embeddings
2. 高斯噪声 latent 初始化 `z ~ N(0,I)`（shape 见下方）
3. 对每个 timestep `t`（从 τ_max→τ_min，通常 28-50 步）：
   - 将 σ = t / τ 作为 sigma 输入
   - MMDiT forward：latent patchify → image tokens + text tokens → joint attention blocks → unpatchify → 输出 vector field v
   - CFG：v_cfg = v_uncond + s · (v_cond − v_uncond)，在 **vector field 层面** 做
   - scheduler（rectified flow Euler）：z_{t-1} = z_t + (t_{t-1} − t_t) · v_cfg
4. VAE decoder → 像素图

#### 关键 tensor shape

| 名称 | shape | 说明 |
|------|-------|------|
| latent | `(B, 16, H/8, W/8)` | 如 1024×1024 像素 → `(1, 16, 128, 128)`。注意 C=16（不是 C=4） |
| image tokens（patchify 后） | `(B, N_img, D)` | N_img = (H/8/p)²，p = patch_size=2 → 1024px → (128/2)²=4096 tokens |
| text tokens（pooled） | `(B, D_pool)` | pooled prompt embedding（来自 T5 或 CLIP pooled output） |
| text tokens（sequence） | `(B, L_text, D_text)` | L_text = max token length（通常 77-512，取决于 encoder），D_text = encoder hidden dim |
| timestep embedding | `(B, D_time)` | Fourier features 编码后经 MLP 投影到 adaLN dim |

**注意**：SD3 的 latent 是 16 通道。这和常见的 SD1.5/SDXL（4 通道）不同，意味着 VAE 压缩率相同但 latent 容量更大，denoiser 对 latent 的处理也有更多信息。

#### 系统推理影响

- **显存瓶颈**：MMDiT 的 full attention 在 token 数多时是主要瓶颈。4096 image tokens + 154 text tokens（双 encoder）= 8500+ tokens 的 attention，O(n²) 增长。1024px 下 128×128 latent → 4096 image tokens，attention 矩阵 4096² × 16bit ×2（QK + AV）≈ 67 MB per layer per attention。50 层就是 3.3 GB activation peak（不含存储中间结果）。
- **可 cache**：text embeddings（CLIP/T5 在推理开始 encode 一次即可，后续 denoising 循环复用）；VAE encoder 对文生图不适用（直接从噪声开始）。
- **不能 cache**：每步 denoiser 的 latent（每步都在更新）；MMDiT attention 的 K/V 矩阵（每步 latent 不同，Q 不同，K/V 也不同，和 LLM 自回归场景完全不一样）。
- **buffer 复用**：latent 可在 scheduler step 中原地更新（不需要 ping-pong）。text embedding 作为固定输入贯穿整个 loop。
- **资源档位**：SD3-Medium（2B 参数）在 1024×1024 + fp16 + offload 下约 8-9 GB，适合。SD3-Large（8B + T5）在 fp16 不开 offload 会超 中等显存配置，需强开 sequential offload 或降分辨率。**结论：SD3-Medium no-T5 路线适合中等显存配置；SD3-Large 极限可跑但需 offload。**

#### 对我的 diffusion_engine 的启发

- `scheduler.py`：需要实现 rectified flow Euler step（z_new = z + dt · v），区别于 score-based ODE。SD3 的 timestep 用对数间距更优（低频更多步 = 高频更少步）。
- `attention.py`：MMDiT 的 joint attention 是一个核心参考，text 流和 image 流在同一个 QKV 投影中处理。我们 toy DiT 可以不做到双流，但至少要知道"双流"是目标方向。
- `dit.py`：patchify/unpatchify 的 patch_size=2 是工业实际值（不是 toy 的 4 或 8）。我们的 toy DiT 应该用 patch_size=2 或 1 来保证 token 数"够规模"。
- `text_conditioning.py`：多 encoder 输出合并（CLIP 的 last hidden + pooled + T5 的 last hidden）是一个实际挑战。我们的 v1 可以先只用单一 encoder 的 last hidden。
- `pipeline.py`：CFG 插入位置需要在 vector field 层面（不是 noise prediction 层面），和传统 DDIM CFG 有本质区别。

### ② FLUX.1 / FLUX 系列

#### 为什么对现代 diffusion 推理重要（≤100 字）

FLUX 是目前最强的 open-weight flow transformer，且提供 schnell（4 步推理）变体。它沿用了 MMDiT 的 joint attention 路线，改进了 adaLN 和 VAE。理解 FLUX 等于验证 SD3 的 rectified flow 范式，并观察 engineering 层面如何降低推理门槛。

#### 模型类型：文生图

#### 核心架构

- **denoiser**：DiT（flow matching transformer），沿用 MMDiT 的 joint attention，但内部 block 结构有调整。schnell 变体专门为 few-step 推理训练（distillation with timestep alignment）。
- **latent 表示**：VAE latent，16 通道（或 4 通道变体，不同版本有差异），8× 下采样。
- **text conditioning**：CLIP + T5 双 encoder，T5 pooling 方式与 SD3 不同（FLUX 更注重 T5 的长文本理解）。schnell 可省略 T5 来降低显存。
- **timestep/sigma conditioning**：Fourier embedding + adaLN-Zero 或 adaLN-Single（单流版本）。
- **attention 结构**：full attention with FlashAttention 兼容。dev/pro 版本使用 QK-normalization 提高训练稳定性和推理数值精度。
- **VAE**：高 latent 通道 VAE（16ch），支持 tiling 以避免大图 OOM。

#### 推理数据流

与 SD3 高度相似：
1. prompt → CLIP + T5（可选）→ text embeddings
2. 噪声 latent → denoising loop → 每步 rectified flow Euler step
3. CFG：schnell 版本通常 cfg=0（distillation 后 guidance 内化），dev/pro 支持 cfg>1
4. VAE decoder（支持 tiling）

**关键差异**：schnell 仅需 4 步（guided distillation 的结果），推理循环极短。这对 受限显存场景意味着 denoiser forward 次数从 28+ 降到 4，总 latency 大幅降低，每步 peak VRAM 不变但总占用时间更短。

#### 关键 tensor shape

| 名称 | shape | 说明 |
|------|-------|------|
| latent（schnell） | `(B, 16, H/8, W/8)` 或 `(B, 4, H/8, W/8)` | 取决于具体 release |
| image tokens | `(B, N_img, D)` | N_img = (H/8/p)²，patch_size 通常为 2 |
| text tokens（CLIP） | `(B, 77, 768/1280)` | |
| text tokens（T5） | `(B, L_t5, 4096)` | L_t5 可高达 512，T5 占用显著 |
| pooled text | `(B, D_pool)` | FLUX 使用 pooling 方式

#### 系统推理影响

- **显存瓶颈**：T5-XXL 是最大显存负担（~5GB fp16）。schnell 省掉 T5 后显存压力大幅下降。denoiser 的 attention 在 1024px 时类似 SD3 规模。
- **可 cache**：CLIP + T5 text embeddings（一次 encode，全程复用）；schnell 的 unconditional embedding 也可 cache（若 cfg=0 则不需要）。
- **不能 cache**：denoiser 每步 latent 和 K/V。
- **buffer 复用**：latent 原地更新 + VAE decoder tiling 减少 decode 显存峰值。
- **资源档位**：FLUX schnell（去 T5 + fp16 + offload）~8-10 GB，适合。FLUX dev（含 T5 + 28 步 + cfg>1）需 sequential offload 或降分辨率。**结论：schnell 路线适合中等显存配置；dev 极限可跑。pro 不开放。**

#### 对我的 diffusion_engine 的启发

- `scheduler.py`：few-step sampling 的 scheduler 接口需要支持可变步数（4 步到 50 步），步数间距需适配 distilled model。
- `text_conditioning.py`：T5 可选的概念，我们的 engine 应该支持"有 T5"和"无 T5"两种 text conditioning 路径，类似 FLUX 的开关设计。
- `vae_stub.py`：VAE tiling 接口，对大分辨率图像（2048px+）需要支持 chunked decode 以避免 decoder OOM。
- `pipeline.py`：schnell 的 few-step loop 作为一个目标 benchmark（4 步出图，目标 latency < 5s on 中等显存配置）。

### ③ Sana：Efficient High-Resolution Image Synthesis

#### 为什么对现代 diffusion 推理重要（≤100 字）

Sana 代表"把 DiT 推向高效率极限"的路线：用 Gemma LLM 代替 CLIP/T5 做 text encoder，用 linear attention 替代 full attention，在保持 1024px+ 质量的同时把推理显存和 latency 大幅度降低。它是 受限显存场景最现实的图像模型。

#### 模型类型：文生图

#### 核心架构

- **denoiser**：DiT，但 attention 改用 **linear attention**（或 efficient attention variant），复杂度从 O(n²) 降到 O(n)。Sana 的 DiT block 内部结构更接近高效 transformer（deep-narrow 或 wide-shallow 取决于版本）。
- **latent 表示**：VAE latent，8× 下采样，4 通道（或 16，取决于 AE 选择），也支持自选 AE（AutoEncoder）。
- **text conditioning**：**Gemma-2B 作为 text encoder**（这是一个关键创新，用一个小 LLM 替代 CLIP+T5 双 encoder）。text token 和 image latent token 的交互方式可能是 cross-attention（不是 MMDiT 的 full joint attention），这样 text token 不参与自注意力。
- **timestep/sigma conditioning**：Fourier + adaLN 或 cross-attention 注入 timestep。
- **attention 结构**：linear attention / efficient attention（具体机制待查论文）。可能用 Performer、Linformer 或 Mamba-style 的状态空间模型。
- **VAE**：可选 AE（如 SD VAE 或自训练 AE），支持高分辨率（4K+ 可能）。

#### 推理数据流

与 SD3 的图像推理流水线相似，但有几个关键差异：
1. text encoder 是 Gemma-2B（LLM），不是 CLIP，意味着 text embedding 维度不是 768/1024，而是 Gemma 的 hidden dim（2304）。
2. attention 不是 O(n²) full attention，这意味着大 latent（高分辨率）时 attention 不再成为主要瓶颈。
3. CFG 可能是标准的 CFG（在 vector field 层面），也可能使用了 negative prompt 的替代方案（待确认）。

#### 关键 tensor shape

| 名称 | shape | 说明 |
|------|-------|------|
| latent | `(B, 4, H/8, W/8)` | 4 通道，或切换 AE 后变化 |
| image tokens | `(B, N_img, D)` | N_img = (H/8/p)²，1024px → 4096 tokens。但 linear attention 使 O(n²) 不成立 |
| text tokens（Gemma） | `(B, L_text, 2304)` | Gemma-2B hidden dim = 2304 |
| text pooled | `(B, 2304)` 或无 | 取决于是否使用 Gemma 的 last token / mean pooling |

**注意**：Sana 的 token 数和 SD3 可比较，但 attention 复杂度不同。这意味着相同的 token 数下 Sana 的显存占用会小于 SD3。

#### 系统推理影响

- **显存瓶颈**：text encoder 从 T5-XXL（~5GB）降到 Gemma-2B（~4GB fp16，但可从 LLM 推理中获得）。attention 从 O(n²) 降到 O(n)，高分辨率下优势极大。VAE decoder 仍可能是高分辨率下的瓶颈（需 tiling）。
- **可 cache**：Gemma text embeddings（一次 encode）；VAE encoder 输出（image-to-image 场景）。
- **不能 cache**：denoiser K/V（和所有 diffusion 一样）。
- **buffer 复用**：latent 原地更新。linear attention 不需要存储完整的 QK attention matrix。
- **资源档位**：**非常合适**。Sana 的设计明确面向 consumer GPU 的高分辨率推理场景。Gemma-2B + linear attention DiT + 可选轻量 AE 组合，预计 8-10 GB 可跑。**结论：适合中等显存配置，是 image reference 的首选。**

#### 对我的 diffusion_engine 的启发

- `attention.py`：linear attention 的实现是我们的一个明确方向。在我们的 toy DiT 中可以先用 full attention，但架构上预留 "efficient attention" 的接口。
- `text_conditioning.py`：LLM-as-text-encoder 是一个独特的思路，我们的 engine 可以先用一个简单的 embedding layer 做 text conditioning，但文本接口应设计成可替换（支持 CLIP、T5、Gemma 等）。
- `memory_manager.py`：linear attention 的 memory tracker 不同于 full attention，不能简单用 n² · 2 · 2bytes 计算显存。
- `pipeline.py`：Sana 的高效路径是我们 toy pipeline 的"理想终点"，最少资源跑通完整 denoising loop。

- arXiv URL：`https://arxiv.org/abs/2410.10629`
- HF model card：`https://huggingface.co/Efficient-Large-Model/Sana_1600M_1024px_diffusers`
- GitHub：`https://github.com/NVlabs/Sana`

### ④ Sora-style video generation（OpenAI Sora 技术说明 + 关键第三方分析）

#### 为什么对现代 diffusion 推理重要（≤100 字）

Sora 虽未开源，但它的技术说明提出了视频生成的**关键架构范式**：spacetime patch、视频 VAE（压缩时间+空间）、DiT 生成 latent 后经视频 decoder 还原。理解这些概念是理解 Wan、Hunyuan、CogVideoX 等后续视频模型的先决条件。

#### 模型类型：文生视频 + image-to-video（文本或图像驱动，生成多种长宽比和时长的视频）

#### 核心架构

- **denoiser**：DiT（diffusion transformer），处理 spacetime patches。
- **latent 表示**：视频 VAE latent，时间+空间下采样。具体压缩比未公开（第三方推测约 4-8× 时间压缩 + 8× 空间压缩）。
- **text conditioning**：未公开具体 text encoder（推测使用 GPT-style 的 caption 重写 + CLIP/T5），但技术说明强调"高度描述性的字幕"是关键。
- **timestep/sigma conditioning**：DiT 标准的 adaLN 或 cross-attention（未公开）。
- **attention 结构**：full attention over spacetime patches（所有帧的所有 patch 互相 attend）。这意味着视频越长，token 数越多，attention 代价增长很快。
- **视频 VAE**：spacetime VAE（也称为 3D VAE），在时间维度和空间维度上同时压缩。这是 Sora 最重要的架构贡献。

**spacetime patch 的概念**：

Sora 将视频视为"三维时空体"，用一个 patch 在 T、H、W 三个维度上同时切分。例如，一个 spacetime patch 可能是 `(1, 2, 2)` 的块（1 帧、2×2 空间块），连续的多个此类 patch 覆盖所有帧。这些 patches 被 flatten 为 token 序列送入 DiT。

与图像 DiT 的区别：图像 DiT 的 patch 只在 H×W 上切，视频 DiT 的 patch 在 T×H×W 上切，所以 token 数 = `(T/t) * (H/h) * (W/w)`。

#### 推理数据流

1. prompt（或图像+prompt）→ text encoder → 条件嵌入
2. 噪声视频 latent 初始化（3D noise：`(B, C, T_latent, H_latent, W_latent)`）
3. denoising loop（DiT 在所有 spacetime tokens 上做 full attention）
4. 视频 VAE decoder → 像素视频

**时间压缩的重要性**：原始视频哪怕是 16 帧 × 256×256，压缩后 T_latent 可能只有 4 帧（4× 时间压缩），H_latent=W_latent=32（8× 空间压缩），总 latent token 数 = 4 × 16 × 16 = 1024 个 spacetime patch tokens。这让 attention 仍然可控。

#### 关键 tensor shape

| 名称 | shape | 说明 |
|------|-------|------|
| 视频 latent | `(B, C, T, H, W)` | 压缩后的视频 latent。C = latent channels（如 4），T = 压缩后的帧数，H/W = 压缩后的空间尺寸 |
| spacetime patch tokens | `(B, N_spacetime, D)` | N_spacetime = `(T/t) * (H/h) * (W/w)`。若 4 帧 latent × 32×32 空间，patch=(1,2,2) → N=4×16×16=1024 |
| text embedding | `(B, L_text, D_text)` | 取决于 encoder |
| timestep embedding | `(B, D_time)` | 同图像 DiT |

#### 系统推理影响

- **显存瓶颈**：video DiT 的 full attention 在帧数增多时 token 数破千到破万，O(n²) 显存需求指数增长。视频 VAE decoder 的显存也是一个瓶颈（解码为像素视频临时占用大量显存）。
- **可 cache**：text embedding（一次 encode）。**VAE encoder** 对 image-to-video 场景可 cache（输入图像编码后的 latent）。
- **不能 cache**：denoiser K/V（和所有 diffusion 一样）。视频 VAE decoder 的中间输出通常不能 cache（非在线场景）。
- **buffer 复用**：latent 原地更新。视频 decode 可以分帧解码或分 chunk 解码来避免一次性分配全部像素 buffer。
- **资源档位**：**不适合大规格**。Sora 未开源且原模型巨大。但是 Sora 的核心概念（spacetime patch + 视频 VAE）是小模型的推理基础。中等显存配置 运行 Sora-scale 不可能，但 Sora 提出的架构范式帮助我们理解为什么 CogVideoX-2B 等小模型可以在中等显存配置上跑。

#### 对我的 diffusion_engine 的启发

- `dit.py`：需支持 spacetime patchify（当前只设计 image patchify）。视频 patchify 需要接受 `(B,C,T,H,W)` 输入并在 `(T,H,W)` 三维上 patchify。
- `attention.py`：spacetime full attention 是扩展方向，当前 image-only 的 attention 只做 2D，需要扩展为 3D attention（所有时空 tokens 互相 attend）。但这也带来更大的 token 数，需要考虑 linear attention 或 sparse attention。
- `vae_stub.py`：视频 VAE decoder 的接口不同于 image VAE，需要"分帧解码"或"chunk decode"接口。
- `memory_manager.py`：需要支持视频 latent buffer（3D shape vs 2D shape 的分配/复用）。
- `pipeline.py`：视频 denoising loop 与图像 loop 的逻辑基本一致，主要是 shape 不同和 scheduler 步数更多。我们的 pipeline 应支持统一接口 + shape dispatch。

**读**：

### ⑤ Wan：Open and Advanced Large-Scale Video Generative Models

#### 为什么对现代 diffusion 推理重要（≤100 字）

Wan 是阿里开源的视频生成模型，公开了 3D VAE 和 DiT 的完整实现。它的 Wan2.1-1.3B 变体是对 对中低显存更友好的 open-weight 视频模型之一。理解 Wan 的 3D VAE + full attention DiT 推理路径，是完成视频 reference inference 的关键。

#### 模型类型：文生视频 + image-to-video

#### 核心架构

- **denoiser**：DiT（video transformer），full attention over spacetime tokens。
- **latent 表示**：3D VAE latent（时间+空间压缩），下采样因子约 4× 时间 + 8× 空间。
- **text conditioning**：T5-XXL（或轻量 encoder），cross-attention 或 adaLN 注入。
- **timestep/sigma conditioning**：Fourier + adaLN。
- **attention 结构**：full attention over all spacetime tokens（所有帧的所有 patches）。对较短视频（≤81 帧）token 总数可控。
- **视频 VAE**：3D VAE（公开），可下载。

#### 推理数据流

同 Sora 框架下的标准视频 diffusion 流程：text encode → noise latent → denoising over spacetime → 3D VAE decode → 视频像素。

**注意**：Wan 的 3D VAE decode 是整段视频一起解码（不是逐帧解码），这意味着 VAE decoder 的显存与总帧数相关。

#### 关键 tensor shape

| 名称 | shape | 说明 |
|------|-------|------|
| 视频 latent | `(B, C, T, H, W)` | T 帧 latent。1.3B 版 81f×832×480 像素 → latent `(1, 16, 21, 104, 60)` 或类似（取决于具体 VAE 下采样） |
| spacetime tokens | `(B, N, D)` | N = 总 token 数，需根据 patch_size 计算 |
| text embedding | `(B, L, 4096)` | T5 hidden dim |

#### 系统推理影响

- **显存瓶颈**：3D VAE decoder 在视频较长时是主要瓶颈（一次性解码所有帧）。DiT full attention 在 token 数大时是次要瓶颈。
- **可 cache**：T5 embedding。image-to-video 场景下的初始图像 latent。
- **不能 cache**：denoiser K/V。3D VAE decoder 逐层激活（通常不能 chunk）。
- **buffer 复用**：latent 原地更新。decode 输出需要较大的临时 pixel buffer。
- **资源档位**：**Wan2.1-1.3B 极限可跑**。81 帧 + 480p + fp16 + offload 约 9-10 GB。降帧数（≤25f）和降分辨率（≤384p）后更稳。Wan2.1-14B 不适合中等显存配置。**结论：1.3B 极限可跑（需 offload + 降规格）；14B 不适合。**

#### 对我的 diffusion_engine 的启发

- `vae_stub.py`：3D VAE 的接口，和我们的 image VAE stub 完全不同。需要定义 `decode_video(latent_3d)` 的接口，以及支持 tiling。
- `attention.py`：视频 full attention 的 token 数可能上千，对于我们的 toy DiT，即使不做视频 full attention，也要在设计中预留"支持 B,T,C,H,W 输入"的类型签名。
- `memory_manager.py`：视频 latent buffer 的 3D shape 分配模式，不同于图像的 2D buffer。
- `pipeline.py`：视频 denoising loop 通常步数更多（50-100 步），CFG 更高（cfg≥6），意味着 denoiser forward 两次（cond + uncond），time 翻倍。

### ⑥ HunyuanVideo：A Systematic Framework for Large Video Generative Models

#### 为什么对现代 diffusion 推理重要（≤100 字）

HunyuanVideo 是目前最系统的视频 diffusion 框架，覆盖了从 text encoder、3D VAE、DiT 设计到数据管线的全链路。它的规模很大（13B+），中等显存配置不适合直接跑，但它的系统化思路对理解视频推理的全链路优化极有价值。

#### 模型类型：文生视频

#### 核心架构

- **denoiser**：DiT（large scale），用 full attention 或可能引入了注意力优化（如 sparse attention 或 multi-scale）。
- **latent 表示**：3D VAE latent（C=16），时间+空间压缩。
- **text conditioning**：多 text encoder 组合（可能含 T5 + CLIP + 自有 captioner），通过 cross-attention 注入。
- **timestep/sigma conditioning**：adaLN-Zero。
- **attention 结构**：full attention（推测）。由于模型巨大（13B+），attention 的 token 数和 hidden dim 都很大。
- **视频 VAE**：自研 3D VAE。

#### 推理数据流

标准视频 diffusion 流程。关键特点是：**frame 数多**（通常 129f 或更多）且**分辨率高**，意味着 latent 的 `(T, H, W)` 都很大，token 数可观。

#### 关键 tensor shape

| 名称 | shape | 说明 |
|------|-------|------|
| 视频 latent | `(B, 16, T, H/8, W/8)` | T 通常 17-33（压缩后）。若原始 129f × 720×1280，压缩时间 4× 后 → T≈33，H≈90，W≈160 |
| spacetime tokens | `(B, N, D)` | N 非常大（33×90×160/p² 量级），attention 内存开销巨大 |
| text embedding | `(B, L, 4096)` | T5 + 其他 encoder |

#### 系统推理影响

- **显存瓶颈**：DiT 的 attention layers。token 数在视频 DiT 中极易破万，O(n²) attention 在中等显存配置上不可行。其次是 VAE decoder 的全帧一次性解码。
- **可 cache**：text embedding。
- **不能 cache**：denoiser K/V。VAE decode 中间层。
- **buffer 复用**：很难复用（token 数太大，需要的 buffer 远超 10GB）。
- **资源档位**：**不适合**。13B+ 模型 + 高 token 数 full attention 在中等显存配置上无法完成完整 50 步推理。即使降帧数（≤9f）和降分辨率（≤256p），模型权重本身 ~26GB fp16 就已超 VRAM。**结论：不适合中等显存配置，主要用于架构理解。如需尝试，参考 community 的 INT4/CPU offload 路径，但不在本项目 scope 内。**

#### 对我的 diffusion_engine 的启发

- `memory_manager.py`：从 HunyuanVideo 的失败中学习"什么不能做"，token 数超过 4096 时 full attention 内存不可接受。这反过来证明我们的 engine 需要 linear attention 或 sparse attention 路径。

- `attention.py`：视频 attention 的 token 爆炸问题，这让我们更明确：attention.py 需要设计 `max_token_budget` 参数，超标时降级为 chunked attention。

### ⑦ CogVideoX：Text-to-Video Diffusion Models with an Expert Transformer

#### 为什么对现代 diffusion 推理重要（≤100 字）

CogVideoX 是智谱开源的视频生成模型，采用 **expert transformer** 架构，通过 3D VAE + 3D causal attention 提升了视频质量和推理稳定性。它的 CogVideoX-2B 是 在中等显存配置上可以跑通的视频模型。同时它的 expert transformer 思路对于 distributed inference 有启发。

#### 模型类型：文生视频 + image-to-video

#### 核心架构

- **denoiser**：3D causal VAE（对视频压缩） + expert transformer（DiT with 3D attention）。3D causal attention 指的是在时间维度上只往前看（causal），保证视频生成的 time consistency。
- **latent 表示**：3D VAE latent，时间+空间压缩。
- **text conditioning**：T5-XXL，通过 cross-attention 或 adaLN 注入 DiT。
- **timestep/sigma conditioning**：Fourier + adaLN（与 SD3 类似）。
- **attention 结构**：3D causal full attention（H×W×T 三个维度上做 attention，但时间维度 causal）。不同于 Sora 的 full spacetime attention（非 causal）。
- **视频 VAE**：3D VAE（causal），压缩比约 4× 时间 + 8× 空间。

**Expert transformer 的含义**：CogVideoX 可能采用了类似 MoE（Mixture of Experts）的 transformer，但论文标题中的 "Expert Transformer" 更可能指的是专门为视频设计的 transformer（非通用 transformer），而非传统 MoE。需待阅读论文确认。

#### 推理数据流

标准视频 diffusion：text encode → noise latent → denoising with 3D causal attention → 3D VAE decode → 视频。

**3D causal attention** 的特殊之处在于：在 denoising 每步中，当前帧只能 attend 当前帧和之前帧的 token，不能 attend 未来帧。这保证了逐帧生成的连贯性，但也限制了 attention 的并行性。

**对视频模型的通用约定提醒**：大部分视频模型使用 `(B, C, T, H, W)` 格式，但是 3D attention 的计算本质是对所有 token（或 causal 过滤的 tokens）做 attention。视频 latent token 数 = `(T_latent) × (H_latent/W_latent)² / patch_size²`。如果 T_latent=13，H_latent=W_latent=40，patch=2，则 N=13×20×20=5200 tokens，对于 attention 仍然很大，但 causal 减少了 KV 缓存（每帧只存到当前帧）。

#### 关键 tensor shape

| 名称 | shape | 说明 |
|------|-------|------|
| 视频 latent | `(B, C, T, H, W)` | 3D VAE latent。CogVideoX-2B 典型：49f×720×480 → latent `(1, 4, 13, 90, 60)` 或类似 |
| spacetime tokens（causal） | `(B, N, D)` | N = `T_latent × (H_latent/p_h) × (W_latent/p_w)` |
| text embedding | `(B, L, 4096)` | T5 |
| timestep embedding | `(B, D)` | adaLN |

#### 系统推理影响

- **显存瓶颈**：3D causal attention 在 token 数大时仍是瓶颈（虽 causal 减少了部分 KV 存储，但 QKV 投影仍是 O(n²) 级别）。T5 text encoder 占用约 5GB fp16。
- **可 cache**：T5 embedding。
- **不能 cache**：denoiser K/V。
- **buffer 复用**：latent 原地更新。因果注意力可以减少每步的中间激活存储（因为 causal mask 使某些 patch 不需要 KV）。
- **资源档位**：**CogVideoX-2B 适合**。2B 参数约 4GB fp16，T5 约 5GB，剩余 1-3GB 给 latent + attention activation。在 49f×480p + steps=50 下约 8-10 GB。降帧数（≤25f）或降分辨率（≤384p）后更舒适。**结论：CogVideoX-2B 适合中等显存配置，是 video reference 的首选。**

#### 对我的 diffusion_engine 的启发

- `attention.py`：3D causal attention 是一个重要的变体，不同于我们的 2D full attention。这让我们意识到 attention.py 需要支持不同的 mask 和 attention 维度（2D vs 3D + causal vs non-causal）。
- `dit.py`：spacetime/3D patchify 的支持，我们的 dit 当前是 image-2D，但需要预留扩展点到 3D。
- `pipeline.py`：视频 pipeline 的 frame 管理，每帧的 denoising 逻辑与图像相似，但需要在跨帧 causal attention 维度上协调。

### ⑧ LTX-Video / LTX 系列

#### 为什么对现代 diffusion 推理重要（≤100 字）

LTX-Video 是目前最快的小型开源视频生成模型之一，采用 real-time DiT 设计，能在 消费级 GPU 上实时生成视频。它的蒸馏和高效 attention 设计对 diffusion_engine 的优化实验有直接参考价值。

#### 模型类型：文生视频 + image-to-video

#### 核心架构

- **denoiser**：紧凑型 DiT（small DiT），用更少的 transformer blocks 和更小的 hidden dim 实现近乎实时的推理速度。
- **latent 表示**：3D VAE latent，但 VAE 压缩更激进（更大压缩比）来减少 latent token 数。
- **text conditioning**：T5-XXL（可替换为更轻 encoder），cross-attention 注入。
- **timestep/sigma conditioning**：Fourier + adaLN。
- **attention 结构**：待确认，可能是 full attention 但 token 总数控制小（激进的 VAE 压缩），或使用 efficient attention（如 FlashAttention 加速）。
- **视频 VAE**：3D VAE（high compression ratio），使 latent T 更短。

#### 推理数据流

与视频 diffusion 标准流程相似，但蒸馏后的 few-step（可能 ≤4 步）推理是关键差异。LTX-Video 2B distilled 版本用极少的 denoising 步骤即可生成视频。

**distilled few-step inference 的价值**：对于 中等显存配置，每一步 denoiser forward（含 attention activation）都消耗显存。从 50 步降到 4 步意味着总 wall time 从 5-10 分钟降到 30 秒-1 分钟，且每步 peak VRAM 相同但总时间大幅缩短。

#### 关键 tensor shape

| 名称 | shape | 说明 |
|------|-------|------|
| 视频 latent | `(B, C, T, H, W)` | 高压缩 VAE 使 T 更短、H/W 更小。如 121f×768×512 → latent `(1, 4, 16, 96, 64)` |
| spacetime tokens | `(B, N, D)` | N 因高 VAE 压缩而更小 |
| text embedding | `(B, L, 4096)` | T5（但更轻的 encoder 也可替换）|

#### 系统推理影响

- **显存瓶颈**：T5 text encoder 仍是主要负担（~5GB）。denoiser 因模型小（2B 参数）且 VAE 激进压缩（token 更少），attention 开销相对小。
- **可 cache**：T5 embedding。
- **不能 cache**：denoiser K/V。
- **buffer 复用**：latent 原地更新。few-step 推理下 buffer 分配次数少。
- **资源档位**：**适合**。LTX-Video 2B distilled 是 在中等显存配置上最现实的视频模型。2B 权重 + T5 + few-step（4-8 步）推理，预计 8-10 GB。**结论：适合中等显存配置，与 CogVideoX-2B 并列 video reference 首选。**

#### 对我的 diffusion_engine 的启发

- `scheduler.py`：few-step scheduler 是核心启发，需要支持 4 步、8 步、16 步等非标准步数，且步数间距需根据 distillation 设定调整。
- `attention.py`：高效 attention（FlashAttention 或 xformers）的兼容性是 LTX-Video 快的关键。我们的 toy 版本可以先用 PyTorch SDPA，但要预留 FlashAttn 接口。
- `pipeline.py`：few-step video pipeline 的架构，可以在我们的 video pipeline 中参考其"仅 4 步出视频"的 loop 结构。
- `memory_manager.py`：few-step 推理下 memory allocation 策略，预分配少许 buffer 后在几个 step 中重复使用。

### ⑨ Pyramid Flow Matching for Efficient Video Generative Modeling

#### 为什么对现代 diffusion 推理重要（≤100 字）

Pyramid Flow Matching 提出了用"金字塔式 flow"（多分辨率/多尺度 flow matching）来提高视频生成效率。它的核心思想，用低分辨率 latent 计算粗粒度 flow，用高分辨率 latent 细化细节，直接降低了大分辨率 latent 下的注意力开销，是 受限显存场景下视频高效生成的理论路径。

#### 模型类型：文生视频

#### 核心架构

- **denoiser**：multi-scale DiT 或 multi-resolution U-Net-like transformer（待确认，Pyramid 流的核心是在不同尺度上运行不同的 flow matching 步骤）。
- **latent 表示**：多分辨率 latent（从极低分辨率到目标分辨率），VAE 的 latent 在不同 pyramid level 上使用不同的尺寸。
- **text conditioning**：CLIP/T5，通过 cross-attention 注入。
- **timestep/sigma conditioning**：adaLN（在不同 resolution 上可能共享或不共享）。
- **attention 结构**：低分辨率阶段 token 少（full attention 可行），高分辨率阶段 token 多（可能需要 efficient attention 或仅在细节需要的区域做 attention）。
- **视频 VAE**：3D VAE，支持多分辨率输出。

**Pyramid flow 的核心思想**（推理视角）：

与其在目标高分辨率 latent 上从头到尾做 denoising（每步的 attention 都是 O(n²)），不如先在低分辨率 latent（n 很小）上做粗粒度去噪，然后在逐步翻倍的 latent 分辨率上做细化去噪。这有几个好处：
- 低分辨率阶段的 attention 成本低
- 在高分辨率阶段，latent 已经接近最终结果（只需"精修"，需要的 denoising 步数也少）
- 总的 attention FLOPs 和显存峰值都降低

#### 推理数据流

1. prompt → text encoder → embeddings
2. 在最低分辨率 latent（如 `(B,C,4,16,16)`）上做最初几步 denoising
3. upsample latent 到下一级（如 `(B,C,8,32,32)`），继续 denoising
4. 重复直到目标分辨率（如 `(B,C,16,64,64)`）
5. 最终 VAE decode

**关键**：在不同 level 之间需要 latent 的 upsampling（可能需要可学习的 upsample layer 或简单插值）。denoiser 在各 level 可以共享或独立。

#### 关键 tensor shape

| 名称 | shape（低分辨率 level） | shape（高分辨率 level） | 说明 |
|------|----------------------|----------------------|------|
| 视频 latent | `(B, C, T/4, H/8, W/8)` | `(B, C, T, H/2, W/2)` | 逐渐 upsample，每级约翻倍 |
| spacetime tokens | `(B, 256, D)` | `(B, 4096, D)` | 低分辨率下 token 极少，attention 成本低 |
| text embedding | `(B, L, D_text)` | 同左 | 各 level 共享 text embedding |

#### 系统推理影响

- **显存瓶颈**：高分辨率 level 的 attention 仍是瓶颈，但因为高分辨率 level 的步数少（可能只需 2-4 步），总 peak VRAM 时间短。pyramid 把 attention 负担分散到不同 scale 的时间段。
- **可 cache**：text embedding（全程共享）；低分辨率阶段的 latent 中间结果（用于高分辨率阶段的初始化）。
- **不能 cache**：denoiser K/V（同所有 diffusion）。
- **buffer 复用**：各 level 的 latent buffer 可以在 level 切换时 resize。低分辨率 buffer 小，高分辨率 buffer 大。buffer manager 需要支持动态 resize。
- **资源档位**：**适合**（理论）。pyramid 思想本身就是为解决大 latent 的 OOM 问题。Pyramid Flow Matching 的具体开源模型可能参数较大，那可能不适合；但 pyramid 概念对 中等显存配置 的自写 engine 来说是"省钱"策略。具体可行性需在实际开源模型上验证。

#### 对我的 diffusion_engine 的启发

- `scheduler.py`：multi-scale scheduler，当前 scheduler 假设 latent 形状固定，pyramid flow 要求 scheduler 在不同分辨率下有不同的 timestep 序列。
- `pipeline.py`：多尺度 denoising loop，不仅有一个 loop，而是在每个 resolution level 上有一个子 loop。这是对当前 pipeline 设计的重大扩展。
- `memory_manager.py`：动态 latent buffer resize，需要在 level 切换时重新分配 latent buffer。对于 中等显存配置，低分辨率阶段可能可以留存更多 buffer 给高分辨率做准备。
- `dit.py`：需要支持不同 resolution 的 latent 输入（patchify 逻辑不变，但输入 shape 可变）。

- GitHub：搜索相关开源实现
- HF model card：待确认

**读**：
- Paper 的 pyramid flow 原理部分
- Architecture section（multi-scale denoiser 的共享策略）
- Inference section（各 level 的步数分配和 upsample 方式）

**输出**：
- T8 产出：`learning/papers/09_pyramid_flow_matching.md`（8 字段完整 + pyramid flow 的推理路径 + 对受限显存配置的价值 + 对 multi-scale pipeline 的启发）

### ⑩ Consistency / Distillation / Few-step Sampling

#### 为什么对现代 diffusion 推理重要（≤100 字）

在 显存预算下，**每减少一步 denoiser forward 就是 1-3 秒延迟和数百 MB 显存 peak 的节省**。Consistency Model、LCM、Turbo、Lightning 等方法通过不同蒸馏策略将 50 步 diffusion 压缩到 4-8 步甚至 1 步，使 diffusion 推理在消费级 GPU 上从"不可接受"变为"实用"。本文是一组方法的总览，覆盖对前面 9 个模型都有影响的 fast sampling 技术。

#### 模型类型：fast sampling（适用所有扩散模型：文生图 + 文生视频）

#### 核心架构

这不是一个具体模型，而是一类**方法/技术**的总览。核心问题是：**如何用极少的去噪步骤（1-8 步）生成高质量结果？**

本文覆盖的典型方法：

1. **Consistency Model（一致性模型）**：将扩散模型的 ODE 轨迹映射为一步映射，任何时间点 t 的噪声 latent 直接映射到最终干净 latent。推理时仅需 1 步即可从纯噪声得到最终结果。
2. **LCM（Latent Consistency Model）**：一致性模型在 latent 空间的做法。专为 Stable Diffusion 系列设计的快速采样。推理 1-4 步。
3. **Turbo / SDXL Turbo / SD3 Turbo**：通过对抗训练 + 蒸馏的"Turbo"变体，将原始 50 步模型蒸馏为 1-4 步推理的各种版本。SD Turbo 在 1 步即可出图，SDXL Turbo 在 1-4 步可出图。
4. **Lightning / AnimateLCM / VideoLCM**：视频模型的快速采样变体。类似 LCM 但针对视频 temporal consistency 优化。
5. **Progressive Distillation**：逐步将多步 denoising 蒸馏为更少步数（如 1024→512→...→8→4→1），与 Rectified Flow 的 few-step 训练兼容。

**关键洞察**：这些方法的基本思路相似，让学生模型（few-step）学习教师模型（full-step）的 ODE 轨迹映射。不同之处在于学习目标和蒸馏策略。

#### 推理数据流

取决于具体方法，但通用 fast sampling 的推理流程是：

1. 文本编码（同原始模型）-可能 cache
2. 噪声 latent 初始化
3. **极少步的 denoising**（1-8 步，而非原始 28-50 步）
4. VAE decode

**与全步推理的区别**：
- scheduler 的步数间隔更大（不是均匀分布，而是学习到的非均匀分布）
- CFG 在某些方法中内化（如 FLUX schnell 使用 cfg=0）
- denoiser forward 的参数不变（权重没变，但可能无需 full-step denoiser 的所有 block，某些方法通过 early exit 加速）

#### 关键 tensor shape

与各自 backbone 模型相同（不改变 shape，只改变步数）。

#### 系统推理影响

- **显存瓶颈**：同 backbone 模型。每步 denoiser 的 peak VRAM 不变（模型权重 + activation 大小同全步版本），但总步数从 50→4 使总 wall time 降低 90%+。这意味着 在中等显存配置下"极限可跑"的模型通过 few-step 蒸馏可能变为"适合"。
- **可 cache**：同 backbone 模型。fast sampling 让 prompt embedding cache 的价值更大（因为总推理时间短，embedding 缓存占总时间的比例更高）。
- **不能 cache**：denoiser K/V（同所有 diffusion）。
- **buffer 复用**：同 backbone 模型。步数少意味着 buffer 分配/释放次数更少。
- **资源档位**：**Fast sampling 本身对受限显存配置尤其有利**。它不降低每步 peak VRAM，但大幅缩短 wall time，同时使本来需要 28+ 步的模型可以在超时前完成。结合 offload，1-4 步推理确保 在中等显存配置上能完成文生图（即便是大模型）。

#### 对我的 diffusion_engine 的启发

- **这是 T16（optimization）的关键输入**。
- `scheduler.py`：需要支持 non-uniform timestep（distilled scheduler），步数间距不是线性的或对数均匀的，而是学习到的。我们的 scheduler 接口需要接受自定义 `step_list`（不仅是 `num_steps`）。
- `pipeline.py`：few-step 推理路径，pipeline 应该支持 `num_steps=4` 这种配置，并在内部调用正确的 scheduler。
- `memory_manager.py`：few-step 推理下的 allocation 策略，步数少意味着预分配 buffer 的价值更大（因为 buffer 复用次数少，预分配开销占总时间比更大）。
- **T16 的 scheduler_benchmark** 应直接比较 full-step（28-50 步）和 few-step（4-8 步）的 latency/quality tradeoff。

## 6. 给 T7/T8 执行者的最终提醒

### 6.1 关于"资源档位现实性"的判断标准

| 判断 | 标准 | 标签 |
|------|------|------|
| **适合** | 模型 ≤ 5B 参数 + fp16 权重 ≤ 10GB + attention token 数少 + 通常可 offload T5 | 🟢 标签 |
| **极限可跑** | 模型 5-13B 或 text encoder 大，需 offload + 强制降规格（≤256p / ≤16f / reduced steps）+ 可能 OOM | 🟡 标签 |
| **不适合** | 模型 > 13B 或 需要 > 中等显存配置 才能加载权重 | 🔴 标签 |

### 6.2 关于"tensor shape"的写入原则

- **必须有具体数字**：不写"latent shape 为 (B,C,H,W)"，要写"latent shape `(1, 16, 128, 128)`（1024px 图像，8× VAE 下采样）"
- **必须有计算**：patch token 数 = `(H/p) × (W/p)`，为有值做这一步
- **视频必须标明形状约定**：`(B,C,T,H,W)` 还是 `(B,T,C,H,W)`，两者都有使用，T7/T8 必须根据实际源码确认

### 6.3 关于"对 diffusion_engine 的启发"

- 必须**具体到模块文件名**：scheduler.py、attention.py、transformer_block.py、dit.py、text_conditioning.py、pipeline.py、memory_manager.py、vae_stub.py
- 不能写"可以学习其设计"这种空话
- 对每个模块的启发 ≤ 2 句话

### 6.4 关于输出文件的命名

- T7: `learning/papers/01_scaling_rectified_flow_transformers_sd3.md`、`02_flux_architecture_notes.md`、`03_sana.md`
- T8: `learning/papers/04_sora_style_video_generation.md` 到 `10_consistency_distillation_fast_sampling.md`
